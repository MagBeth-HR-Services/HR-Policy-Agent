# How to Finish the Horizon HR Policy Agent

Engineering, evaluation, deployment, and required markdown files are done. What remains is people work: record the demo, invite the grader, and submit.

This file replaces the earlier implementation plan. That plan still described 10 eval cases without gold answers, missing traces, and an undeployed app. Those items are no longer true.

Score **2+** is passing. The repo is aimed at a **4–5**: a working deployed demo with visible MCP traces, a 20–30 case eval with gold answers and the named metrics, and the three required markdown files.

## Current status (11 September 2026)

### Done

- Single-service architecture: FastAPI + LangGraph + two stdio FastMCP servers + Chroma + SQLite + OpenRouter
- `/api/chat` returns `answer`, `citations`, `snippets` (on each citation), and `tool_trace`
- Chat UI shows citations and the tool trace; `/health` reports MCP connectivity
- Live app: https://horizon-hr-policy-agent.onrender.com/
- Health: https://horizon-hr-policy-agent.onrender.com/health
- Both demonstration workflows verified on the live URL
- Evaluation set of **exactly 24 cases**, `EVAL-001` through `EVAL-024`
- **Every case has a `gold_answer`** (gold / expected answer)
- Full evaluation 24/24; no-policy-search ablation 18/24

- `design-and-evaluation.md`, `ai-tooling.md`, `deployed.md`, and README include the live URL
- GitHub Actions CI, including MCP discovery/call coverage in pytest
- Render Standard (2 GB) deploy; architecture stays free-tier compatible; instance is paid because MiniLM plus three Python processes exceed 512 MB

## Remaining work: demo and submit

Official demo rules:

- 7–10 minute screen-share with voiceover
- Every group member on camera and speaking
- Every group member shows government ID
- **Deployed** app, two agentic tasks end-to-end
- For **each** task: tool names, arguments, outputs, citations, final behavior
- Short walkthrough: design, deployment, CI/CD, evaluation
- Share GitHub with `quantic-grader`
- One member submits both links
- Group agreement last page if submitting as a group
- Late submit is allowed; grading may be delayed
- Questions: msaie+projects@quantic.edu

Suggested order:

1. Architecture (one service, two MCP servers, RAG + SQLite)
2. CI green on GitHub Actions
3. Live URL + `/health` (MCP status)
4. Task 1 on the live app: `I am employee E1001. Can I take three PTO days next week?` Narrate tools, args, outputs, citations. Do not approve PTO.
5. Task 2 on the live app: `I am employee E1002. Can I work from another country for six weeks?` Narrate POL-004 (often also security), 20-business-day limit, multi-department review. Do not approve.
6. One failure path: invalid ID (`1002`) or out of scope (payroll / medical / send email)
7. Metrics from `design-and-evaluation.md`: 24/24, ablation 18/24, p50/p95, 17.65 s first chat

Immediately before recording, re-run both live workflows so the cold/first-chat wait is already done if possible.

After grading: suspend the Render Standard service so it stops billing.
